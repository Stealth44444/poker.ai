# AI 핸디 10인 홀덤 토너먼트 — 설계 문서

날짜: 2026-08-12

## 1. 개요

Next.js 기반 웹앱에서, 플레이어가 3D 1인칭 시점으로 10인 홀덤 테이블에 앉아
서로 다른 성격을 가진 AI 핸디 9명과 싱글 테이블 노리밋 홀덤 토너먼트를
플레이하는 게임. AI 상대의 의사결정과 테이블 톡은 OpenAI API로 구동한다.

## 2. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Next.js | 프론트+백엔드 통합. OpenAI 키는 서버(API Route)에서만 사용 |
| 3D 렌더링 | React Three Fiber + drei (Three.js) | 1인칭 카메라, 마우스 드래그 회전 |
| AI 캐릭터 | Ready Player Me (Mixamo 호환 리그) + Mixamo 애니메이션 | 무료, 스타일라이즈드 3D 아바타 |
| AI 의사결정 | OpenAI `gpt-4o-mini` + function calling | 구조화된 액션 강제, 실패 시 폴백 |
| 핸드 평가 | `pokersolver` (또는 동급 검증 라이브러리) | 직접 구현하지 않음 — 엣지케이스 리스크 회피 |
| 상태 관리 | 세션 쿠키 키의 서버 인메모리 저장소 | MVP 범위, 새로고침 시 초기화 |

## 3. 포커 엔진 & 토너먼트 로직

- **게임 상태:** 10석 테이블, 덱, 커뮤니티 카드, 팟(사이드팟 포함), 현재 베팅
  라운드, 딜러 버튼 위치, 블라인드 레벨.
- **베팅 로직:** 표준 노리밋 홀덤 규칙 — 폴드/체크/콜/벳/레이즈/올인. 다중
  올인 발생 시 사이드팟 자동 계산.
- **핸드 평가:** 쇼다운 시 최고 조합 판정은 검증된 라이브러리에 위임.
- **토너먼트 구조:** 시작 스택(기본값 10,000, 조정 가능), 블라인드는 **핸드
  수 기준**으로 증가(기본 10핸드마다 레벨업, 실제 시간 타이머 아님). 스택이
  0이 되면 즉시 탈락. 1명이 남으면 토너먼트 종료.
- **확장성:** `Table`/`Player`는 제네릭 배열 기반 구조로 모델링한다. MVP는
  테이블을 1개만 인스턴스화하지만, 데이터 모델 자체는 여러 테이블을 담을 수
  있는 형태로 만들어 향후 멀티테이블 + 테이블 밸런싱을 얹기 쉽게 한다.

## 4. AI 상대 시스템 (OpenAI 연동)

- AI 9명은 각각 `{ name, style, description, avatarId }` 프로필을 가진다.
  `style`은 공격적/타이트/루즈/블러퍼 등으로 구분되어 서로 다른 플레이
  경향을 만든다.
- 서버가 매 AI 턴마다 현재 게임 상태 + 해당 AI 프로필로 프롬프트를 구성하고,
  OpenAI에 **function calling**으로 `{ action, amount?, tableTalk? }` 형태의
  구조화된 응답을 강제한다.
- 프롬프트 컨텍스트: 홀카드, 보드, 팟 크기, 콜 금액, 전원 스택, 이번 핸드의
  액션 히스토리, 성격 설명, 그리고 **엔진이 사전 계산한 유효 액션 목록**
  (모델이 불법 액션을 반환하지 못하게 방지).
- **오류 처리:** API 타임아웃/오류 시 안전한 기본 행동으로 폴백한다 — 체크가
  가능하면 체크, 아니면 폴드. 이 폴백이 없으면 API 장애 시 게임이 멈춘다.
- 테이블 톡: 액션과 함께 짧은 플레이버 텍스트를 반환받아, 재생 시 해당
  아바타 위에 말풍선으로 표시한다.

## 5. 3D 씬 & 비주얼

- **카메라:** 플레이어 좌석 위치에 고정. 마우스 드래그로 회전만 가능(이동
  없음). 실제 VR 헤드셋(WebXR) 지원은 MVP 범위 밖.
- **아바타:** Ready Player Me로 생성한 캐릭터를 Mixamo 호환 풀바디 리그로
  익스포트하고, Mixamo의 무료 애니메이션(대기, 카드 확인, 베팅/칩 밀기,
  폴드, 승패 리액션)을 리타겟팅해 사용한다.
- **테이블/소품:** 3D 테이블, 3D 카드 모델(앞/뒤 텍스처 스왑으로 랭크·수트
  표시), 인스턴싱된 3D 칩 스택(칩 개수에 따라 높이 반영). 카드·칩은 2D
  이미지 스프라이트가 아니라 3D 모델로 통일해 아바타와 시각적 일관성을
  유지한다.
- **내 카드:** 1인칭 시점이라 본인 아바타 몸은 보이지 않으므로, 카메라 앞에
  "들어 올린" 형태의 오버레이로 카드를 표시한다.
- **성능:** GLTF 압축(Draco/meshopt), 칩은 인스턴싱 렌더링, 카메라 정면이
  아닌 아바타는 LOD를 낮춘다.

## 6. 턴 진행 / 실시간 UX

웹소켓이나 SSE 없이 단일 요청-응답으로 처리한다:

1. 플레이어가 액션을 하거나 새 핸드가 시작됨
2. 클라이언트가 서버에 요청
3. 서버는 **사람 차례가 다시 오거나 핸드가 종료될 때까지** AI 턴을 전부
   순차적으로 계산(OpenAI 호출 포함)
4. 서버는 이벤트 로그(행동자, 액션, 금액, 테이블 톡, 결과 상태 스냅샷)를
   배열로 반환
5. 클라이언트는 일정 딜레이(예: 이벤트당 1.2초)를 두고 순차 재생하며 아바타
   애니메이션·칩 이동·말풍선을 연출
6. 재생이 끝나면 사람 차례 액션 버튼을 표시하거나, 핸드 종료 시 쇼다운
   연출 후 "다음 핸드" 진행

## 7. 상태 관리

세션 쿠키를 키로 하는 서버 인메모리 저장소에 `TournamentState`
(테이블, 플레이어들, 현재 핸드 히스토리, 블라인드 레벨, 누적 핸드 수)를
전부 보관한다. 새로고침이나 서버 재시작 시 게임은 초기화된다.

## 8. MVP 범위

**포함:**
- 10인 싱글 테이블 토너먼트 (사람 1명 + AI 9명)
- 핸드 수 기준 블라인드 증가
- 서로 다른 성격의 AI + 간단한 테이블 톡
- 3D 1인칭 시점 (일반 화면, 마우스 드래그 회전)
- 스타일라이즈드 3D 아바타 (Ready Player Me + Mixamo)
- 세션 중 인메모리 상태 (영속화 없음)

**명시적으로 제외 (향후 확장 대상):**
- 멀티테이블 + 테이블 밸런싱
- DB 기반 영속화/재개
- SSE/웹소켓 실시간 스트리밍
- 실제 VR 헤드셋(WebXR) 지원
- 포토리얼리스틱 아바타
- 실제 다중 사용자(사람 vs 사람) 멀티플레이

**지금 심어두는 확장 포인트:**
- Table/Player 데이터 모델을 제네릭 배열 구조로 설계 (멀티테이블 대비)
- AI 의사결정 로직을 인터페이스 뒤로 분리 (모델/페르소나 교체 용이)
- 토너먼트 상태 머신을 테이블 로직과 분리 (향후 멀티테이블 오케스트레이션이
  감쌀 수 있게)
